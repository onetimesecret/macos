`SealedChip.availability` is `Availability::Local(LocalValue)` or `Availability::Peer { kind, size }`; `meta()` is `Option`, `excerpt()` and `size_label()` are empty for a peer, `duplicate()` is `Option`. `OTSSNAP5` puts an availability tag ahead of the value; `OTSSNAP4` is still read through `ChipLayout::Valued`. v5 is unshipped, so units 2 and 3 extend the chip record in place.

Unit 2: `import_update` returns the identities a batch stands that the page lacks; `ChipRoster` is gone from both refusal enums (no restore or local path used it). The store's `admit`, `follow_sentinels` (inside `settle_document`), `rehome_values` (inside `entomb`) and `take_out_standings` do ADR-0058 points 1 to 3 and 8.

**Why:** ADR-0058 (proposed) lets a peer keep a record whose value lives on another device, so a sync never stalls on an object it cannot import.

**How to apply:**
- Loro's `to_delta` coalesces two adjacent sentinels with the same chip mark into one piece; `runs_of` (via `split_marked`) reads only a U+FFFC under a chip mark as a chip, one per sentinel; any other marked character is ink. Any position math over runs depends on that.
- A record moves only between readable pages, and the page it leaves forgets its undo (a step there could stand the sentinel with no record). A detached record replaces a standing record with no value; a detached record with no value drops where a value stands.
- `delete_chip` then drops every record with no value for the burned identity on readable pages (no ledger event) and takes out its standings; a dropped detached one forgets its page's undo.
- `entomb` mutates its page now, so its old `#[expect(clippy::needless_pass_by_value)]` had to go.
- A core helper an ffi test needs must be `#[cfg(any(test, feature = "test-util"))] pub`; a `#[cfg(test)]` helper in core is invisible to ffi tests. `SheetStore::stand_peer_record` mints a random identity, so a test needing a peer record for a real object builds it by shipping a batch.
- Two restores of equivalent snapshots re-snapshot byte for byte (Loro's export is deterministic), so `assert_eq!(a.snapshot(0), b.snapshot(0))` is a usable equivalence check.
- `copy_out_chip` reads attached chips only; read a detached chip's bytes in a core test through `local().unwrap().bytes`.
- Unit 3 (shell, 2026-10-23): `stand_peer_record` returns `Result` now (an FFI seam must never panic); the seam `companion_test_stand_peer_record` is named in two seam regexes, `scripts/package-app.sh` and `scripts/verify-release-core.sh`, so a new gated seam needs both.
- `mergeIntoShownStorage` compares objects by chip id only, so a face change under the mounted page (availability, a peer's rename) needs `restateChipFaces(onSheet:)` after it; unmounted pages are rebuilt whole.
- `ChipInfo.available` decodes with `decodeIfPresent ?? true`, so older fixtures still decode. `readerReason` translates both value-elsewhere refusals into sealed content wording (ADR-0055 rule 3).
- The only burn path in the shell is Burn Local Copy after a successful conceal, so hiding Create One-Time Link plus the core's conceal refusal keeps the burn from being offered.

- Unit 4 (core metadata, 2026-10-23): routes live in `crates/core/src/metadata.rs`. The writer is set in `companion_sync_configure` (stored identity only, never mints, since configure already reads the Keychain at launch) and in `ensure_engine`. A name with no version (an `OTSSNAP4` restore) restates at counter 0. `stand_in` folds the replaced record's newer name into the arriving value. A no op rename takes no version. Two test stores mint different page uuids, so `apply_object_metadata` in a test takes the receiver's own page uuid.
- `OTSSNAP5` chip tail is name, name version (flag, u64 LE, 32 bytes), note; a hand built v5 fixture with a note must write the version flag.
- Review fixes (2026-10-23): the core's `restated` set marks only pages other than the route's own (stand_in, take_detached, drop_records_with_no_value, a learned keep_newer_metadata, stand_plan sources); the shell drains it at the top of `refresh()`, the one funnel every core route already passes. `stand_in` keeps the standing record's chip id, so the moving record's own id dies; a test that asserts the original id after a value follows will fail. `companion_test_stand_peer_record` takes `of_chip` (0 for a fresh identity) so a Swift test can stand another page's identity. `Placed::elsewhere` counts beside `unavailable`, never inside it. A metadata entry for a page with no sheet is dropped, and `entomb` purges held entries for its page.
- Review fixes B (2026-10-23): `version_of` in metadata.rs is the one rule both `of` and `adopt` read, so an unversioned name compares as `(0, this store's writer)`; `absorb` and `adopt` take the writer. `stand_in` records old id to new in `moved_chips` (64, never persisted, cleared by restore because restore mints chip ids from 1); only `record_sent` and `mark_chip_concealed` resolve through it. `delete_chip` and `chip_stands` stay literal: the shell's `refresh()` drops a conceal draft whose chip id is gone, so Burn Local Copy never sees a moved id. `stand_peer_record_as` inserts the sentinel before pushing the record; `document.fail_writes_after(0)` reaches the refusal. Dirty metadata for a page goes in `entomb` (`forget_page_metadata`), not on every `note_metadata`.

- Unit 5 (Metadata envelope, 2026-10-23, uncommitted at write): the restate owed is `PageTracking.metadata_restated_at: Option<u64>`, compared with the chain's epoch in the sweep, so every epoch move restates every enrolled page without hooking each commit site. `withdraw_ops` drops queued `Metadata` too, so every withdraw of a live page (`settle_frontier`, the stale batch rewind) must reset the stamp, or a frame seal refused twice loses the restate. A successful attach resets every stamp (ADR-0058 point 5 says "at attach"). Wire ids for objects and writers are parsed by a strict `lower_hex`; `page_from_wire` stays lenient (`from_str_radix` takes `+`). Driver tests have a `Devices` two companion harness on one `SHARED_SECRET` chain; `FakeRelay` is private to the session tests.

- Unit 6 (note CRDT in core, 2026-10-23, uncommitted at write): store routes live in `note.rs`; `note_version` takes `&mut self` because a note with no log (v4, a clone) has no version until its document is minted. Loro's `decode_import_blob_meta` copies the oplog into non-wiping memory, so there is no arena-free way to read a log's version. The v5 note field is text then a required log (empty for none); hand built v5 fixtures use `note_field`. `perform_ceremony` returns an `OTSFRM02` frame (u64 LE prefixes); `adopt_key_frame` still takes a bare Loro blob. `Sheet::compact` compacts attached notes on every solo rung transition too. `note_pending` is its own deque, keyed by page uuid and object.
- Unit 7 (NoteOps envelope, 2026-10-23, uncommitted at write): `PageTracking.notes` maps object to a `NoteCursor` (frontier, acked); `StagedBatch.notes` records them per page at seal. A 409 rewinds no export frontier, page or note (client protocol §4.4 table row: "export frontier not rewound"), though the unit brief said it rewinds. `withdraw_ops` is page wide, so `settle_frontier` settles only standing notes on their rebuild and rewinds detached ones to acked, or their withdrawn ops would leave a gap peers refuse as `MissingHistory`. The stale batch drop withdraws when the page or any note rewound. The sweep drops a cursor whose record left `notes_on`.
- Unit 8 (records, 2026-10-23, uncommitted at write): client protocol, core interface, Law 0001 (three record with no value rows, a lifecycle row, the 2026-10-23 peer record amendment), FOUNDATIONS B1/B2 and plan row 61. The brief's banned word scan flags pre-existing words in any one-line table row you touch; scan inserted words with `git diff --word-diff=porcelain` instead. `chip_face` lives in `content_json.rs`, not `lib.rs`. A burn of a record with no value is refused, which ADR-0058's Consequences say ("It cannot copy, drag, link, conceal or burn the value.") and no Decision point names. `docs/plans/names-in-place.md` line 32 still cites the retired `sync_carries_no_object_*` tests.

- Review fixes C (2026-10-23, uncommitted at write): `place_chip` compacts or owes the ceremony after any seal with `len_u16 > 0` (text and image, all four `seal_*_at` routes). Page `undo`/`redo` run `take_out_standings`; a redo only stands a burned identity again when the undo ran before the burn. Metadata and note batches fall through to the identity's records on other readable pages (those pages go in `restated`) and drain by identity, still held under the page they were sent for so its end purges them. `note_pending` is a `PendingNotes` (256 batches, 256 KiB, byte total in a field); an empty note batch is `Malformed` first, and Loro refuses empty bytes too. `adopt_key_frame` on a due page returns `Ok(())` changing nothing, while `apply_remote_update` still imports into a due page. `set_writer` restamps zero writer name versions and marks them changed. Client protocol rows Metadata and NoteOps and the core interface (lines near 163 and 308) still say a batch waits when its own page lacks the record.

- Review fixes D (2026-10-23, uncommitted at write): a note's history is shared once exported, merged, framed or restored with a log (`Body::Document { shared }`; a resting note is shared by its log). `Note::compact` (every page compaction, standing and detached) keeps a shared note whole and rests an unshared one as text alone; the ceremony calls `Note::rebuild` per standing note. `history()` gives no log for an unshared note, so `notes_of` needed no change. `import_ink_update` takes a `Lineage`: `Own` refuses `UnrelatedHistory` (vv diff on the fork plus `get_change` deps), `Any` only for `merge_shared`. A resting note with no log takes a batch whole only when blank or the batch spells its text. Consequence: two devices typing one record's first note apart never merge until a key frame. `note_version` still wakes resting notes (the driver's `settle_frontier` after a ceremony).

- Review fixes E (2026-10-23, uncommitted at write): `sweep_outbound` queues every gone page's terminal after the live walk. `ItemId::random` is time ordered, so a loop waiting for a fresh id to sort before an older one never ends; `Devices::second_page` adopts a hand built id instead. With no verified peer a terminal's rotation is solo and `settle_frontier` withdraws the anchor page's ops, so a two device test of a move needs `Devices::pair()` (peer records plus an attach roster) to make it a ballot. The driver test `deliver` now trusts paired markers and settles a commit as `pump` does. A ballot sends the seal's ink in the epoch 0 batch (ADR-0058 point 10 names it); each committer's own rebuild sheds it.

- Review fixes F (2026-10-23, uncommitted at write): `drop_stale_batch` keeps a stale batch's `Terminal` envelopes in `SyncSession.held_terminals`; `sweep_outbound` calls `release_held_terminals` after the live walk. A hand `chain.advance` does not move the per page `PageChannel` epochs (`commit_advance` does), so a peer meets the next batch as `rejoin_required`; a two device stale drop needs a real ballot: A `cycle_rung`s a third page, B's acceptance is acked, B's next batch goes unanswered, then both commit. `drain_nothing` before any sweep makes nothing current: the channel is created by the first `queue_terminal` attempt.

- Review fixes G (2026-10-23, uncommitted at write): `apply_entry` adopts into every record of the object on readable pages (no early return on the named page) and marks the others with `note_metadata` and `restated`; `drain_pending_metadata` marks its page when an entry held for another page changed the record. `set_chip_name` takes `after(max name_version over all records)` and writes every record, attached or detached. A detached record with no value never coexists with a standing one after a settle (`follow_sentinels` moves it), so a test of a detached record plus a standing one detaches the value first and stands the peer record after. The shell's `setChipName` does not call `refresh()`, so a rename's `restated` pages wait for the next refresh.
