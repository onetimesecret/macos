v10 · the labels come off

You're right — I carried the caption forward from the original cell anatomy without ever questioning it. Examined, the label answers a classifier's question ("what species is this?") that nobody at the panel is asking. The owner's question is "which one is this?" — and the fragment already answers it, because the owner pasted it twenty minutes ago: ghp_… is a GitHub token to anyone who owns one, postgres:// announces itself, PEM headers are literally self-labelling. Meanwhile the classifier costs a regex bank that must chase every new token format, guesses wrong just often enough to erode trust, and — worst — makes a privacy product that parses your secrets to be helpful. "We never read what you paste" is a stronger position than "we read it to protect you." So: the regex bank is deleted. Everything a chip shows is now built without reading the content — a simple excerpt (a fixed number of characters from the start and the end, no parsing) plus the clipboard's own metadata (kind, dimensions, byte size, filename, line count). Detection was also quietly doing a second job in v9 — deciding what gets masked. That decision is now made by origin, not content (1c): typed text stays readable, pasted content lands masked.

new rule: the app never reads what you paste — fragments are simple excerpts, counts are counts, names come from the clipboard's metadata · everything else unchanged: one countdown per sheet · hover → actions, never content · excluded from capture · ladder 1h→7d, default 8h

The label's jobs — and what handles each one now
"which one is this?"
the visible fragment — a fixed number of characters from the start and end, middle hidden · it only has to be recognized by the person who pasted it, not identified by a stranger
"what species is this?"
dropped — nobody was asking · schemes, vendor prefixes and PEM headers self-identify; the label was mostly reading the answer off the value and handing it back
naming · context
the author's own typed line above the paste — the text file already taught everyone this ritual; the app stops competing with it (1b)
mask or keep readable (v9's hidden detection job)
decided by origin, not content — typed text stays readable, pasted content is masked (1c) · stricter than v9, which displayed "benign" pastes on screen and so quietly broke the no-plaintext rule again
kind · size (images, files)
the clipboard's own metadata — content type, dimensions, byte size, filename — read without ever opening the contents
the regex bank
deleted — nothing to maintain, no wrong guesses, less security-sensitive code to audit
what is honestly lost
the app can no longer notice when you type a secret by hand ("looks like a key — mask it?") — masking typed text becomes a manual step: select it, choose seal · and a harmless paste (an address, say) gets masked too; if that proves annoying in practice, a second paste command that keeps text visible (⌥⌘V) is the candidate fix — undecided
