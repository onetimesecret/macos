Several of its load-bearing readings have since been overtaken: `PageModel` now takes injectable seams (issue #53), the save status and force save it records as absent both shipped (issues #49 and #46), the boot-session tests it credits for case 3 were deleted with the arm they tested, and `docs/qa/verification-procedures/` now holds seven documents rather than one. ## 1. What the code does today

**Swift shell (shell/Sources/OnetimePad, shell/Sources/CompanionKit).** The debounced-on-mutation write model is genuinely implemented. `markDirty()` fires on store mutations, arms a 2.0 s one-shot timer anchored to the first mark of a burst (`SaveSchedule.arm()` returns nil while a write is pending, PageModel.swift:174-192, :446), and `saveState()` is the single synchronous main-actor write for both files (PageModel.swift:812-894). `ProcessInfo.disableSuddenTermination()` is really wired and refcounted (PageModel.swift:101-141), the one shipping bundle really declares `NSSupportsSuddenTermination` (shell/OnetimePad-Info.plist:56), and the latch discharges only on a write that reported success (PageModel.swift:892). Quit is a flush, not the mechanism (BackdropApp.swift:121-151). There is exactly one executable target, OnetimePad (shell/Package.swift:36-70); `dist/CompanionApp.app` and `dist/CompanionBackdrop.app` are stale artifacts no script produces.

**Rust sealing (crates/ffi/src/persist.rs, crates/core/src/persist.rs).** The state envelope is `OTSSEAL2 ‖ boot_uuid[16] ‖ wall_ms[8] ‖ mono_ns[8]` with the whole 40 byte header as AEAD associated data (persist.rs:155, :206-211, :636-659). The content key is HKDF-SHA256 with the boot half as salt and the keychain half as IKM (persist.rs:374-381). The boot half's filename folds `kern.bootsessionuuid` into the HKDF salt (persist.rs:415-431) and lives in `_CS_DARWIN_USER_TEMP_DIR` at mode 0600 (persist.rs:463-481). The write path is `create_new` temp, `sync_all` (F_FULLFSYNC on Darwin), `rename(2)`, parent dir fsync (persist.rs:1152-1210). TTL math is sleep-inclusive monotonic end to end (crates/core/src/clock.rs:88-123, crates/ffi/src/lib.rs:1185-1190), enforced by one Swift timer armed from `companion_next_event_ms` (PageModel.swift:1872-1900) and backstopped on the load path (crates/core/src/persist.rs:578-615).

**Credentials and signing (crates/credentials, scripts/).** Data protection items carry `kSecUseDataProtectionKeychain` plus `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` (lib.rs:637-646); login keychain items name the default keychain explicitly and carry no protection class (lib.rs:647-651). The 2026-08-10 amendment is implemented as written: reads and `exists` fall through to the login keychain, deletes reach both (lib.rs:1004-1053). No build in this tree currently reaches the data protection keychain: `scripts/package-app.sh:163-203` applies the entitlement only when `CODESIGN_IDENTITY`, a scraped Team ID, and `PROVISIONING_PROFILE` are all present, and `scripts/local.env:1-10` sets only the first.

**Verification (tests, docs/qa, dogfood).** Roughly 100 Rust tests cover the envelope, boot bind, rotation, atomic replace, tamper and truncation rejection, and TTL drain on restore, all in CI (.github/workflows/ci.yml:34,49,67). The Swift side has one persistence test file, `shell/Tests/CompanionKitTests/StateLicenceTests.swift`, and it tests only pure static predicates and two value types. No test constructs a `PageModel`, calls `loadStateIfNeeded`/`saveState`, touches a real file, or fires the debounce timer. `docs/qa/verification-procedures/` holds one document, about drag tracking, never run. The premise that `fix/page-persist` is unmerged is wrong: it landed as PR #39, merge commit c1ffb3c, and its worktree is clean at an ancestor of main.

## 4. The decision

Whether staged content survives a restart. Four shapes were costed.

**A. Keep the boot bound, re-scope #47 to within-boot durability.** Cheapest, no format change. But it is not a free status quo: ADR:38 has to be corrected downward, and ADR-0011's TTL ladder tops out at 7d with the rationale "will I need this next week", which is unreachable on any machine that reboots weekly. Under A the ladder must be capped at 24h or every rung relabelled "or until restart".

**B. Drop the boot bound; TTL becomes the only lifetime mechanism.** Persist the second key half in the app support directory instead of the per-boot temp name, drop the header boot check, and age snapshots by wall clock guarded by a persisted nondecreasing high-water mark.

**C. Durability follows the TTL rung.** Rungs of 8h and under stay boot-bound, 24h and up persist. Two files, two keys, plus migration whenever the user clicks the TTL wheel across the threshold.

**D. Per-page "Keep across restart" toggle.** Boot-bound by default with an opt-in flag.

### Recommendation: B

Supersede ADR-0012's staged-content section with a new ADR. Re-scope nothing in #47.

**The boot bound does not currently deliver what the ADR sells, so keeping it is not free.** ADR:38 claims per-boot rotation of the keychain half. `rotate_key_halves` has one caller, the `BootMismatch` arm at crates/ffi/src/lib.rs:1260, reachable only when a parseable state file exists. Empty the store before shutdown and the next boot reuses the previous keychain half (crates/ffi/src/persist.rs:231-244). ADR:45's escape clause already admits the old boot half's bytes may still be on disk if the temp directory was not cleared. Combine the two and an extracted keychain item plus an uncleared temp directory yields a live content key across reboots. The mechanism is weaker than the prose in exactly the way this project's history predicts.

**The invariant the monotonic rule protects survives without the monotonic clock.** ADR:63 exists for one sentence: a stepped clock must never extend a secret's life. Persist a nondecreasing wall-clock high-water mark on each save and charge the ceiling when `now` reads earlier than it. A stepped clock then costs life, never grants it, which is the same fail-safe direction `monotonic_away_ms` already implements at crates/ffi/src/lib.rs:1185-1190 by returning `u64::MAX` on a suspect stamp. The property is preserved; only the mechanism changes.

**The residual exposure B accepts is one the ADR already accepted, in larger form.** ADR:82 keeps content-derived page titles under a long-lived, never-rotated key for a rolling ninety days and calls that the bound an auditor can state in one sentence. B puts content under a long-lived key for at most seven days behind the same keychain ACL. If ninety days of "prod DB credentials" titles is acceptable, seven days of the body is the same trade, shorter.

**C and D cost more and buy less.** Both keep two ciphertext paths alive and double the one module ADR:30 and ADR:100 stake the entire audit story on. C gives one click on the TTL label a hidden second meaning. D's default outcome is the failure that opened the issue (docs/dogfood/ABERRATIONS.md:32, work lost to an accepted system update), and an opt-in nobody clicks at 2 a.m. does not fix a default that loses data. I would take C only if a written threat model demanded crypto-erasure for short-lived pages, and none exists.

**B deletes two live defects rather than fixing them:** the sysctl read failure that today destroys the live session's content on a transient error (crates/ffi/src/persist.rs:933-936 into crates/ffi/src/lib.rs:1249-1272), and reboot deaths that leave no ledger record (crates/ffi/src/lib.rs:1249-1273), which stop happening because nothing dies undecryptable.

**Trap to state explicitly in the ADR.** Removing the boot check is not sufficient. Restore hands the core `saved_wall_ms` plus `monotonic_away_ms(sleep_inclusive_ns(), saved_mono_ns)` (crates/ffi/src/lib.rs:1285-1289). Both readings come from a clock that restarts at reboot, so after a restart `checked_sub` returns `None`, `away_ms` becomes `u64::MAX`, and every page expires the instant the surface opens. Silent, and it reads as "restore worked, everything had expired."

**Preconditions, all in scope for the same ADR:** wall-clock aging with the persisted high-water guard, never bare wall clock; a replacement rotation trigger, since `BootMismatch` is rotation's only caller today (rotate both halves when the store empties and on explicit Clear, and make `erase_state` unlink the persistent half); the 7d ceiling and page-and-link TTL granularity stay exactly as they are; ship #49 and #46 with or before this, because a silently withheld save licence that today costs one boot session will cost seven days of work.

**Fixes required regardless of which branch wins:** `markDirty()` in `copyOutChip` (PageModel.swift:1543-1547); distinguish "read a different boot session" from "could not read the sysctl" so a read failure refuses to open and refuses to erase; a content-side clear gesture so a rejected snapshot does not brick persistence for the session; correct ADR:47 and ADR:58 to name `package-app.sh` and one bundle.

## 5. Consequences either way

### Under A (keep the boot bound)

- **Code.** Correct the sysctl fail-closed path so a read failure is not destructive. Emit reboot-death `expired` records from the ledger's own live `created`/`sealed` UUIDs, which needs no decryption. Add `markDirty()` to `copyOutChip`. Ship #49 and #46. Sweep orphaned `*.tmp` at launch.
- **ADR.** Amend. Correct line 38 to say rotation is file-triggered. Add a Consequences line that the 3d and 7d rungs are capped by restart, and amend ADR-0011's ladder to match. Add reboot-death records to line 79's event list. Fix lines 47 and 58.
- **Tests.** Write all seven manual procedures under `docs/qa/verification-procedures/`, since the matrix is testable only at hardware level for cases 3, 4 and 6. Add the first `PageModel` integration test, which requires making the state directory and credential store injectable.

### Under B (drop the boot bound)

- **Code.** crates/ffi/src/persist.rs:416-418 stop folding `current_boot_uuid()` into the name salt. persist.rs:463-466 point the half's directory at the app support state directory, which threads the state path into `persist`, since it currently derives its own. persist.rs:622-660 and :683-749 drop the boot field from `StateHeader` and bump `FILE_MAGIC` from `OTSSEAL2`; the header length changes, so the AEAD associated data changes and every existing file is refused. crates/ffi/src/lib.rs:1249-1272 delete the `BootMismatch` arm, which invalidates the ordering rationale behind the post-restore `fileExists` probe at PageModel.swift:629-654. crates/ffi/src/lib.rs:1185-1190 replace `monotonic_away_ms` with wall-clock aging plus the high-water guard. Add the replacement rotation trigger and the content-side clear. Nothing in `crates/credentials` changes and no `kSecAttrAccessible` value changes.
- **ADR.** Supersede, not amend. New ADR replacing lines 34 to 51 wholesale, including the crypto-erasure claim at 41, the deterministic backstop at 43, the does-not-claim paragraph at 45, and the boot-versus-user-session paragraph at 51. Rewrite line 63 into wall clock plus high-water mark. Rewrite consequences 98, 100 (two mechanical checks becomes one) and 101, which gains "ciphertext and both key halves persist across boot sessions". Untouched: framing (22-27), item identity (32), keychain tiering (47, 49), the whole ledger section, write policy (53-59).
- **Tests.** Case 3 flips from "verified as discard" to "verified as restore", which invalidates crates/ffi/src/persist.rs:1683-1979 and crates/ffi/src/lib.rs:3349-3407 as written. New required tests: cross-session restore ages correctly by wall clock; a stepped-back clock charges the ceiling; the high-water mark is persisted and monotonic; the new rotation trigger fires on empty-store and on Clear.

### Irreversible either way, once B ships

- **The format break.** Any of B, C, D bumps `FILE_MAGIC` and refuses every existing `state.sealed` with no migration path (crates/ffi/src/persist.rs:622-660). Users lose whatever is staged, once. That makes it the moment to take every other pending format change at the same time: the durable-Tab versus expiring-Page split (docs/dogfood/ABERRATIONS.md, triaged "graduate to ADR", no issue, changes the persisted object graph) and ADR-0013's interaction count, declared not derivable from the op log and therefore an obligation on the snapshot format that nothing implements. Two format breaks cost users twice.
- **Key lifetime.** Key material that previously died at every restart becomes durable. Any copy already captured by a backup, an APFS local snapshot, or a forensic image stays live. Reverting later does not retroactively kill a half that was persistent while it was captured.
- **The published claim.** "Crypto-erasure at reboot is the primary mechanism" (ADR:41) and "both dead or rotated after reboot" (ADR:98) shape README and marketing copy. Retracting them is a public claim change under ADR-0007's terminology rules. The honest replacement is bounded by policy and TTL, not bounded by boot.
- **Wall-clock aging for content.** ADR:63 reserved wall clock for the ledger only (ADR:83). Going back to monotonic later requires another format change and another user-visible loss.

## 6. Open questions for the maintainer

1. Do you accept wall-clock aging for content, guarded by a persisted nondecreasing high-water mark, in place of ADR:63's monotonic rule? Restart survival is impossible without it, and this is the one security property B actually trades.
2. With `BootMismatch` gone, what triggers key rotation? Proposal is rotate both halves when the store empties and on explicit Clear, plus `erase_state` unlinking the persistent half. If that is not enough, rotation leaves the design entirely.
3. Does the durable-Tab versus expiring-Page split (ABERRATIONS.md, no issue, no ADR) get decided inside this milestone? It changes the persisted object graph, and the format break should happen once, not twice.
4. Should ADR-0011's TTL ladder change? Under B the 3d and 7d rungs finally mean what they say. Under A they never do on a machine that reboots weekly.
5. Does #49 owe a content-side recovery gesture, or only surfacing? Today a snapshot that authenticates but fails core validation withholds the save licence for the whole boot session with no user-reachable clear, while the ledger has one. Under B that failure lasts until the user finds it rather than until reboot.
