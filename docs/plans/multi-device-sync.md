# Multi device sync

**GitHub milestone:** [Multi device sync](https://github.com/onetimesecret/macos/milestone/3)  
**Status:** Active  
**Source of execution status:** GitHub issues, not this document.

## Goal

A user with two machines can open the same page on both and see the same text, without the server that carries it between them ever being able to read a word. Sync is off until the user turns it on, the pad keeps working with no account and no network, and a page that dies on one machine dies on the other.

The shape is already decided in part. [ADR-0013](../adr/0013-document-provenance-and-block-metadata.md) settles that sync follows broadcast rules rather than archive rules: a second device joins the stream at the current key frame and structurally never receives the ops behind it, compaction under collaboration is a coordinated protocol event rather than a local one, and a relay holds at most the encrypted deltas since the last key frame, purged by the ceremony, so what a compromised relay can accumulate is bounded by one GOP rather than by the life of the page (`docs/adr/0013-document-provenance-and-block-metadata.md:411-431`, `:509-511`). The relay itself is decided in [ADR-0021](../adr/0021-multi-device-sync-over-a-blind-relay.md), accepted 2026-08-25; the number moved from 0020, which the day projection decision had already taken. What that ADR reaches into is spread across the tree: the key derivation and its rotation triggers in `crates/ffi/src/persist.rs`, the Loro seam in `crates/core/src/document.rs`, the compaction triggers and the expiry clock in `crates/core/src/store.rs`, the monotonic discipline in `crates/core/src/clock.rs`, and the network boundary that `crates/transport/src/lib.rs` enforces. [ADR-0016](../adr/0016-content-persists-across-restart.md) section 3 constrains the keys, because the keychain half is deliberately `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` so that no durable key rides iCloud Keychain to a second machine (`docs/adr/0016-content-persists-across-restart.md:202-262`). [ADR-0017](../adr/0017-durable-tabs-expiring-pages.md) decides that the rung is a tab property and the page is the thing that expires, which is the object the deadline rule has to agree about.

The tension this plan opened with was real: the design documents forbade what ADR-0013 licensed, the anti goal read "not a sync service" without qualification, and the network boundary was drawn as exactly one outbound destination. Pass 1 resolved it in writing (#92, landed with PR #106) rather than papering over it, and the doctrine now reads as it will be built. `docs/spec/design/01-problem-space.md:175-180` scopes the anti goal to "Not a general sync service": where the pad moves a page between a person's own devices, it does so on the pad's lifecycle and inherits every expiry rule rather than suspending them. `docs/spec/design/03-design-principles.md:66-69` keeps the iCloud answer at No while naming a first-party relay between enrolled devices as a separate question, and `:88-96` states the principle the relay must live inside: every destination is one the user enrolled and can see, and what is forbidden is not automatic traffic but unaccounted traffic. `docs/spec/design/05-technical-direction.md:107-117` draws the boundary at two outbound destinations, TLS only: the configured OTS server on an explicit conceal, and the relay, only for a page shared to the user's own enrolled devices. `crates/transport/src/lib.rs:44` still refuses any URL that does not start with `https://` before a socket opens, and its allowlist widens from one entry to two rather than being removed.

## Completion criteria

- The design documents and ADR-0013 say the same thing about sync, and the network boundary is written as it will be rather than as it was.
- [ADR-0021](../adr/0021-multi-device-sync-over-a-blind-relay.md) records the relay decision, the pairing model, the metadata the relay unavoidably learns, and the join rule, each as a numbered section with its rejected alternatives named.
- A delta can leave one document, cross a wire, and land in another without a Loro type crossing out of `crates/core/src/document.rs` and without a peer id crossing a ceremony boundary.
- Ciphertext the relay retained before a ceremony cannot be opened after it, proven by a test rather than promised by a policy.
- Two devices holding one page agree on when it dies: the earlier deadline fires, except that a live hold suspends the countdown everywhere, because a paused page stays paused until it is unpaused (ADR-0021 section 6).
- A device is trusted because a human verified it, not because it presented an account token.
- With sync off, the app is indistinguishable from today's app, and every degraded sync state has a sentence a user can act on.

## Pass 1: reconcile the doctrine before deciding anything (complete)

**Tracking:** [#92](https://github.com/onetimesecret/macos/issues/92), closed by PR #106.

This pass preceded every other one because an ADR cannot contradict the documents it sits under. It came out as a narrowing, not a retraction, and the Goal section above cites the doctrine as it now reads. The anti goal became "not a general sync service" with the pad's own lifecycle as the carve-out, the network boundary was restated for two outbound destinations with everything else holding (TLS only, no telemetry, no update pings beyond the launch time release feed check), and the only-network-operation principle became the unaccounted-traffic rule: no destination the user did not enroll, no payload the app would not show them, no retention on a relay beyond the page's own expiry (`docs/spec/design/03-design-principles.md:88-96`). The conditions sync must meet are written where implementation issues can cite them: off by default, opt in per page, visibly live while it is live, and a core loop that still works with no account and no network per `docs/design-brief.md:76-77`. Every amendment was made in place with a date, the house convention.

## Pass 2: decide the relay, the join, and the clock (decided)

**Tracking:** [#93](https://github.com/onetimesecret/macos/issues/93), closed by [ADR-0021](../adr/0021-multi-device-sync-over-a-blind-relay.md); [#94](https://github.com/onetimesecret/macos/issues/94) and [#100](https://github.com/onetimesecret/macos/issues/100) remain open for the details the decisions leave to them.

ADR-0021, accepted 2026-08-25, is one document and these were three issues, because two of the decisions it records were large enough to argue separately. It follows the layout of ADR-0016 and ADR-0017 so issues can cite "ADR-0021 section 4", and it records: the relay storage contract, one GOP of encrypted deltas plus exactly one sealed key frame superseded at each ceremony (section 1); purge as structural, per GOP keys rotated at the ceremony so retained relay ciphertext is undecryptable, never phrased as a deletion promise (section 2); the account gating the channel while pairing establishes device trust, with the relay never holding a key (section 3); the metadata admission as a section of its own, six enumerated channels held to the ledger's content free discipline (section 4); the RFC 9420 external commit join, with cryptographic authorization and enrollment split from backfill (section 5); the expiry rule (section 6); ADR-0010's two-stores stance surviving unamended (section 7); and no key ever riding iCloud Keychain (section 8). This pass preceded pass 3 because every seam below is built against an answer here: the transport key exists to make purge structural, the pairing exchange exists because the account is not the device, and the delta seam has to carry what the deadline rule says travels, the policy `(created_wall_ms, ttl_ms)` and never the deadline (`crates/core/src/clock.rs:19-31`, `crates/ffi/src/lib.rs:1503-1507`).

The two items drafted as recommendations were both ratified the same day (PR #113). The one-key-frame join stands as drafted. The fail-closed hold was rejected: a paused page stays paused until it is unpaused, the hold is the user's instruction rather than a clock candidate, and a device that was offline past the original deadline entombs its own copy locally but may not publish the terminal marker, rejoining the still-live page at the current key frame when it reconnects.

- #94 keeps the two details the join decision leaves open: what supersession means when a ceremony fails partway, and what the waiting device shows the user, which is pass 5's degraded-state sentence rather than a silent spinner.
- #100 lands the expiry rule with the two tests ADR-0021 section 6 names: two stores driven through a shared expiry proving the earlier deadline fires, and a hold on one store surviving the other's offline deadline, with the returning store rejoining rather than killing it. It also amends `clock.rs`'s module doc in place: monotonic stays authoritative for every locally observed interval, and the replicated policy is a second wall clock reader beside the restart gap, subject to the same never-extend arithmetic. The second device's `expire_due` (`crates/core/src/store.rs:1266-1290`) writes to its own ledger, so two wall stamped ledgers describing one death is expected and correct.

## Pass 3: build the seams and the keys

**Tracking:** [#95](https://github.com/onetimesecret/macos/issues/95), [#96](https://github.com/onetimesecret/macos/issues/96), [#97](https://github.com/onetimesecret/macos/issues/97), [#98](https://github.com/onetimesecret/macos/issues/98)

Four independent pieces that can proceed in parallel now that ADR-0021 is accepted, because none of them needs another's output to be designed. All four precede pass 4: the protocol cannot be specified without knowing what a delta looks like on the wire, and the ceremony cannot be coordinated without a key to rotate.

- #95, the per GOP key. What exists is one content key per form factor per state directory, `HKDF(keychain_half, file_half)` under a single versioned info string (`crates/ffi/src/persist.rs:204`, `:445-452`), with a second info string deriving the file half's filename (`:214`). Rotation exists as `rotate_key_halves` but fires on the two triggers ADR-0016 section 6 names rather than at a compaction boundary, and it erases rather than deriving forward (`crates/ffi/src/persist.rs:376-382`). Add a third derivation branch producing a per GOP transport key under its own versioned info string, documented beside the other two. Settle first whether it descends from the content key or from a separate pairing secret, because that answer decides whether a paired device that has never held a page can decrypt anything.
- #95 also has to answer ADR-0016 section 3. The keychain half is `ThisDeviceOnly` precisely to keep a durable key out of iCloud Keychain (`docs/adr/0016-content-persists-across-restart.md:202-262`), so the transport key cannot ride the existing mechanism to a second device and must arrive by pairing. The ledger key stays outside all of this: rotation must never touch it (`crates/ffi/src/persist.rs:188-196`).
- #96, the delta seam. `crates/core/src/document.rs` is deliberately the only file that touches Loro, and it exports exactly one shape: the full document with history included (`:214-220`), imported by a merge that is never partially applied (`:225-230`). Across the C ABI the shell speaks JSON op batches through `companion_sheet_apply_ops`, with `companion_sheet_sync_document` as the whole document recovery path. Deltas since a known point, and the version vector needed to ask for them, have no representation anywhere in the tree. Add both directions in the crate private style the file enforces, with the same reject whole discipline on import, and decide whether the frontier travels as opaque bytes or as structured JSON like the op batches.
- #96 has two constraints it must not break. A remote update that adds or removes a chip has to reach the same invariant check the local path goes through, or the chip roster and the document's marks fall out of one to one agreement, which restore treats as damage and refuses (`crates/core/src/persist.rs:152-156`). And a peer id must not cross a ceremony boundary: the compaction rebuild types the body run by run into a fresh document precisely because the spike measured that a `StateOnly` export keeps the authoring peer id (`crates/core/src/document.rs:363-395`). Decide what to do about `set_change_merge_interval(0)`, set so every commit stays its own change, which is what makes provenance work and what makes deltas chattier (`crates/core/src/document.rs:82-89`).
- #97, device pairing. Two devices must trust each other directly, with a per device identity key, a human performed verification the user is able to fail, and a path by which the content key or the transport key reaches the new device given that the keychain half cannot travel. The nearest worked art is the BYOE local service, where the app holds an Ed25519 identity key in the Keychain as a third account and answers a challenge nonce before plaintext moves (`docs/spec/feature/byoe/local-service.md:103-111`); the BYOE README's own retraction is worth reading before adopting any of it. Revocation belongs here too: a lost device loses access at the next ceremony at the latest, and the user needs a way to say so. Pairing secrets stay separate from the conceal credentials in `crates/credentials`, and clearing one does not clear the other.
- #98, account access. Auth today is HTTP Basic with an `extid` and an API token, isolated behind the `AuthStrategy` trait so a swap is additive (`crates/ots-client/src/auth.rs:10-13`), with PASETO bearer tokens already named as phase 2 (`docs/spec/design/05-technical-direction.md:139`) and the desktop app's needs for long lived tokens, device shaped identity and offline grace already asked as open question 21 (`docs/spec/design/06-open-questions.md:180-183`). OAuth gates the relay channel and nothing else. Settle which flow a desktop app with no browser and no redirect target uses, token lifetime and refresh for an app that sleeps for days, and what the relay does with a token that expires mid session. Sync credentials stay separate from conceal credentials, because a conceal is a deliberate act and sync is a background one, and an expired token disables sync while leaving the pad fully usable.

## Pass 4: specify the protocol and coordinate the ceremony

**Tracking:** [#99](https://github.com/onetimesecret/macos/issues/99), [#101](https://github.com/onetimesecret/macos/issues/101)

These two are one event described from two sides, which is why they share a pass: the ceremony is a protocol message set, and the protocol's storage contract only means anything because the ceremony ends it. Both need pass 3's key and delta seam in hand, and both precede pass 5 because the app cannot show a user a state the protocol has not defined.

- #99 turns ADR-0013's bound into a protocol: the channel model and what a device attaches to, the message set for attach, publish, fetch since frontier and announce ceremony, the storage contract as a numbered section checked against ADR-0021 section 1, and the backpressure limits a page held open for a week with every commit its own change makes necessary.
- #99 must say what happens when a device announces a ceremony and then dies before the others follow, and must check the metadata admission (ADR-0021 section 4) against the protocol as specified rather than as imagined.
- #99 has a transport constraint it cannot ignore. `crates/transport/src/lib.rs:42-49` hard refuses any non `https://` URL before a socket opens. A relay wanting a long lived connection either lives inside that constraint or the constraint is amended deliberately, on the terms the doctrine now sets (the allowlist widens from one entry to two rather than being removed), not incidentally as a side effect of shipping.
- #99 also owes the server side. The relay work is filed privately in onetimesecret-internal#8 while it is a skunkworks build, with this issue naming the interface it must implement. It runs as a separate service on Fly.io Machines (Sprites for hibernation between syncs) rather than inside the OTS app, so the relay iterates on its own cadence and holds nothing durable. A device offline for longer than one GOP recovers by rejoining at the current key frame, never by asking for history.
- #101 makes compaction coordinated. Today it is purely local: `Sheet::compact` graduates block metadata and rebuilds the document, fired from an accepted `cycle_rung` (`crates/core/src/store.rs:1093-1115`), an accepted `set_rung` (`:1122-1141`), and a pause top up (`:1160-1196`). With peers, each of those becomes a proposal the other devices accept, perform, and confirm.
- #101's interesting case is failure. A device asleep during a ceremony holds pre ceremony history and rejoins carrying it, and it is either refused until it drops that history or the ceremony was never a boundary. Rotating the transport key and rebuilding the document are two halves of one event and must not be able to half happen. A ceremony proposed and not confirmed by every attached device leaves everyone on the old GOP rather than splitting them across a boundary.
- #101 must leave solo behaviour exactly as it is. With no peer attached a device still compacts at rung transitions, with a test that proves it, and the pad must not appear frozen while a ceremony runs on a gesture the user just made.

## Pass 5: give sync a surface

**Tracking:** [#102](https://github.com/onetimesecret/macos/issues/102)

Last, because every sentence the app shows names a state some earlier pass defined, and because the off switch is the promise pass 1 either kept or amended. Whatever the documents settle, the app is where a user finds out that something now leaves the machine without a gesture.

- Sync is off by default, and the app with sync off is indistinguishable from today's app.
- Enrolment is where #97's verification appears: the fingerprint or short authentication string on both devices, with a way to fail it, plus a device list showing what is attached, when each was last seen, and how to revoke one.
- Status follows the persistence word the header already carries from the write lifecycle, saving, saved and save failed, rather than inventing a second vocabulary.
- Every degraded state gets its own sentence and none of them are silent: an expired token from #98, a relay that cannot be reached, a device waiting to join with no peer awake from #94, and a page being edited elsewhere.
- No second settings surface. The controls live in the existing Settings surface with the keymap file as the source of any shortcut, and a control that should exist only while it is needed reuses the shape of the ledger's clear button behind its unavailable ledger banner. `HiddenUI` from #78 is the recent lesson about affordances that had not earned their place.

## Dogfood loop

Keep new observations in [ABERRATIONS.md](../dogfood/ABERRATIONS.md). Graduate each one to an ADR, GitHub issue, plan, or [DOGFOOD.md](../dogfood/DOGFOOD.md) guidance once it is understood. Link the destination from the original observation. Sync observations belong here too, and one of them outranks the rest: anything that leaves the machine when the user did not ask for it is an aberration whatever the documents say, and it goes straight to an issue.
