Sixteen ways back

Nearly every product in the incumbent set can show you an earlier state. Only a handful invented a way of showing it that nobody else copied. These are those — redrawn from documentation, source code and locale files, and grouped by the shape the history actually takes.

Every editor promises undo. Almost none promise it survives closing the window, and fewer still will show you the thing you are about to overwrite.

v5 · current 14:22:07

Read these as drawings. This session has no route to a browser or a logged-in account, so nothing here is a captured screenshot. Each panel is rebuilt from the primary source — Etherpad's timeslider.css, Anytype's history.scss, VS Code's localHistoryCommands.ts, published help centres and changelogs — and reproduces layout, control wording and colour semantics, not pixel metrics. Where a source could not confirm a detail, the panel says so in red rather than inventing it.

The history is a tree, and it says so

3 plates

Undo is a stack everywhere. In these three, redoing after an undo doesn't destroy the abandoned future — it becomes a sibling, and the interface hands you a way to walk sideways into it.

The move. A whole buffer given over to the shape of your own hesitation. Moving the cursor up or down the tree undoes and redoes the real file live; b and f step sideways into a branch you abandoned twenty minutes ago. Nothing is ever truncated — a new edit after an undo grows a new limb instead of amputating the old one.

The history is a shelf of states you mount and compare

4 plates

Discrete, addressable, often nameable. The interesting variation is not the list — everyone has a list — but what the product does when you ask it to hold two states up against each other, and what it does to the shelf when you take one down.

The history is a diff, and the byline is the payload

2 plates

Here the question isn't "what did it used to say" but "who put that there". Both of these treat authorship as a property of the text itself rather than of the revision, which is a different data model and a visibly different screen.

The history happens whether or not you ask

3 plates

No save-a-version button, no snapshot ritual. These capture in the background and then face the harder design problem: how to present a history nobody deliberately made, without drowning the user in it.

Vim persistent undo

tree
:undolist
number  changes  when           saved
     7        2  09:14              1
     9        3  11:02
    12        4  4 minutes ago
:earlier 10m
4 changes; before #9 11:02
:set undofile undodir=~/.vim/undo
  undo history survives :q and reboot
:earlier 1f  " back one file-write
:later 30s

The move. Time as a first-class argument to a command. :earlier 10m doesn't step ten times through an undo stack — it asks the buffer what it looked like ten minutes ago and puts you there, crossing branch boundaries to get it. 1f counts in file-writes instead of minutes.

Persistence
off by default; set undofile writes the whole tree beside the file and reloads it on reopen
List
:undolist shows every leaf, with a saved-write marker
UI
none in core. The undotree plugin draws the same tree Emacs draws, in a side pane
Kinship
same model as undo-tree; opposite interface. One is a picture, the other a sentence

Method, and what to distrust

Sixteen products drawn from the 150-odd examined in the 29 August outing, selected on one test: does the interface do something no one else in the set does? Products with a competent but conventional list-and-restore panel — Notion, Evernote, Dropbox Paper, Airtable, Standard Notes, JetBrains, Lightroom, Canva — are absent for that reason, not because they scored badly.

Panels reproduce layout, control wording and colour semantics from primary sources; they do not reproduce pixel metrics, real typefaces or exact spacing, and no screenshot was captured. Three panels carry a red note where a source could not confirm a detail. The Linear panel is the weakest — its wording is documented verbatim, its layout is not documented anywhere public, and the margin placement shown is an inference from one line about narrow windows.
