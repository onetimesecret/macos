# macOS application context and deliberate paste

Research reference, checked 2026-10-01. This corrects the supplied AppKit guidance; it is not an accepted architecture decision or product law. API descriptions below are quotations or paraphrases of Apple documentation. Recommendations are explicitly proposals. No macOS integration was runtime-tested for this research.

## Scope and source authority

The user’s instruction for this exploration is:

> we are not interested in background clipboard collection, or any automatic copying of information that is not readily available in the given context. Paths, applications, and what NSPasteboard/UTI can afford.

This is a task constraint, not evidence that the existing implementation enforces it. The proposed baseline uses supplied paths, ordinary application identity, and representations delivered through explicit paste, drop, or a requested Services action. Accessibility inspection, screen capture, Apple Events interrogation, Spotlight scans, and a continuously recorded application history are outside this baseline. These are exclusions from this exploration, not claims that macOS prohibits those APIs generally.

Apple API documentation and shipped SDK declarations are primary sources for platform contracts and availability. Apple Support documents user-facing conventions. An Apple DTS forum answer can clarify undocumented behavior; the original forum report is only a developer’s observation. The supplied research, this document, mockups, and delivery notes do not establish project guarantees. Project attribution follows the [source-authority instructions](../../AGENTS.md#normative-claims); the user has requested runtime validation before compatibility promises.

## Application identity: useful, limited context

`NSWorkspace.shared.runningApplications` returns `NSRunningApplication` instances. Identity and presentation information include bundle identifier, process identifier, localized name, icon, and activation policy. Filtering `.regular` gives a useful list of ordinary applications, not a documented reproduction of Command–Tab membership or ordering. Apple defines `.regular` as “The application is an ordinary app that appears in the Dock and may have a user interface.” The list documentation states, “The order of the array is unspecified”. `.onlyActive` is not an activation policy case. [Activation policy](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/regular), [running applications](https://developer.apple.com/documentation/appkit/nsworkspace/runningapplications), [application information](https://developer.apple.com/documentation/appkit/nsrunningapplication)

`NSWorkspace.didActivateApplicationNotification` identifies the affected application through `applicationUserInfoKey`. It carries no documented departure-application, departure-window, Command–Tab reason, or clipboard-source payload. Observe it through `NSWorkspace.shared.notificationCenter`, rather than Foundation’s default notification center. A previously observed activation, or sampling `frontmostApplication` before deliberately activating OnetimePad, can supply an application hint. Calling that hint the app the user copied from would be an inference, not provenance. Missed observations, startup, helpers, and intervening activations limit what can be reconstructed. [Activation notification](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification), [frontmost application](https://developer.apple.com/documentation/appkit/nsworkspace/frontmostapplication)

The cited workspace references do not provide an exact blanket guarantee that these operations will never require a permission prompt under every supported configuration. The attachment’s stronger promise is unsupported by those references. A narrow prototype should verify actual behavior in the intended signed and sandboxed build.

An **app-switch journal** means a retained sequence such as *10:02 Zed → 10:03 Safari → 10:04 OnetimePad*, potentially with timestamps or durations. This was explanatory language, not an Apple API or proposed feature. An ephemeral hint at summon time is a different design from keeping that sequence.

**Proposal:** an explicit app association could narrow a pad chooser when no folder is supplied: Terminal could suggest shell scratch notes; a browser could suggest reading notes. Its value declines when one app serves many projects. Zed alone cannot distinguish two worktrees. If a supplied directory already identifies the pad set, app association may add nothing. It should earn its place through that concrete shortcut, with ambiguous cases left for the user to choose.

## Paths: accept supplied context

A Choose dialog, a file/folder drop, a pasted file URL, an existing OnetimePad document, or an explicit editor/command-line handoff can provide a path. `NSOpenPanel` exposes selected URLs and can be configured to choose directories. Apple describes the panel as an interface “when you want to prompt the user to select one or more files or directories.” A supplied path identifies a location; it does not establish which document another app currently has focused. [Open and Save panels](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/UsingtheOpenandSavePanels/UsingtheOpenandSavePanels.html), [NSOpenPanel](https://developer.apple.com/documentation/appkit/nsopenpanel)

Two corrections to the attachment:

- `NSDocumentController.recentDocumentURLs` concerns the calling application’s document controller and Open Recent state, not a system-wide inventory of other applications’ open documents. [Document controller](https://developer.apple.com/documentation/appkit/nsdocumentcontroller), [recent URLs](https://developer.apple.com/documentation/appkit/nsdocumentcontroller/recentdocumenturls)
- `kAEOpenDocuments` is an event instructing an app to open supplied documents, not a query for its open-document list. Apple’s exact description starts: “Event that provides an application with a list of documents to open.” Any scripting query would depend on that target’s separate scripting interface. [Open Documents event](https://developer.apple.com/documentation/coreservices/kaeopendocuments)

The window-list permission claim also needs correction. The attachment cited a forum report about `kCGWindowOwnerName`. Apple DTS explains: “which keys are populated without permission is undocumented and may change at any time.” That report does not establish a stable macOS-26 redaction rule for owner names or window titles. Window inspection is unnecessary for the supplied-context baseline. [Apple DTS clarification](https://developer.apple.com/forums/thread/839069)

## Pasteboard: representations, not guaranteed provenance

`NSPasteboard` transfers typed data through a server shared by applications. An item can offer several representations of the same selection, identified by uniform type identifiers; modern code can use `UTType` alongside `NSPasteboard.PasteboardType`. Common possibilities are `.string`, `.rtf`, `.rtfd`, `.html`, `.fileURL`, `.pdf`, `.png`, and `.tiff`. Rich formats carry structured content and formatting, not merely a universal formatting-metadata field. The source decides what it offers; the receiver chooses a supported representation. No particular Safari, TextEdit, or other application format combination is guaranteed by this API. Custom types are possible; calling a type app-private does not establish confidentiality. [Pasteboard](https://developer.apple.com/documentation/appkit/nspasteboard), [pasteboard types](https://developer.apple.com/documentation/appkit/nspasteboard/pasteboardtype), [uniform types](https://developer.apple.com/documentation/uniformtypeidentifiers)

`NSTextView.pasteAsPlainText(_:)` is documented as: “Inserts the contents of the pasteboard into the receiver’s text as plain text.” **Paste and Match Style** is a user-facing operation that adopts surrounding styling; do not equate every app’s implementation with reading only `.string`. Apple’s conventional shortcut is Option–Shift–Command–V, and individual applications control their actions. Neither action creates a separate clipboard channel. [Plain-text action](https://developer.apple.com/documentation/appkit/nstextview/pasteasplaintext(_:)), [Apple paste conventions](https://support.apple.com/102553)

Implementation observation, not a product contract: OnetimePad’s current [default keymap](../../shell/Sources/CompanionKit/Resources/default-keymap.json) maps `cmd-shift-v` to `clipboard::Seal`. Its [ordinary paste route](../../shell/Sources/CompanionKit/InkEditorView.swift) calls `pasteAsPlainText`, with an optional automatic code-fencing path when language detection is enabled. A future formatting conversion needs its own agreed semantics and command.

Additional affordances, with corrected limits:

- `pasteboardItems` models multiple items; each item may have multiple representations. `readObjects(forClasses:options:)` can request strings, attributed strings, URLs, images, or other conforming objects. `prepareForNewContents` is a writing operation that clears prior contents, not a multi-item read helper. [Pasteboard items](https://developer.apple.com/documentation/appkit/nspasteboarditem), [object reading](https://developer.apple.com/documentation/appkit/nspasteboard/readobjects(forclasses:options:)), [preparing contents](https://developer.apple.com/documentation/appkit/nspasteboard/preparefornewcontents(with:))
- `changeCount` tracks ownership changes. Apple states it “increments each time the pasteboard ownership changes.” It is not a timestamp or source identity. No public `NSPasteboard.updatedAt` member was found in the checked API reference or installed SDK header; that attachment claim is unsupported. Background polling is outside the requested scope. [Change count](https://developer.apple.com/documentation/appkit/nspasteboard/changecount)
- `setDataProvider(_:forTypes:)` can supply representations lazily when requested. A file promise can instead arrange delivery of a file to a drop destination; these are related mechanisms, not interchangeable guarantees of immediately available content. [Data provider](https://developer.apple.com/documentation/appkit/nspasteboarditem/setdataprovider(_:fortypes:)), [file promise receiver](https://developer.apple.com/documentation/appkit/nsfilepromisereceiver)
- Drag/drop reuses pasteboard representations. Read the pasteboard passed by `NSDraggingInfo.draggingPasteboard`; reuse conversion logic while preserving the distinct user action. Services also supplies a deliberate inter-app transfer path. [Dragging pasteboard](https://developer.apple.com/documentation/appkit/nsdragginginfo/draggingpasteboard), [Services](https://developer.apple.com/documentation/appkit/nspasteboard)
- `.find` is the shared find pasteboard, not a private inter-app channel. Apple explicitly calls it the “global find pasteboard”. [Find metadata](https://developer.apple.com/documentation/appkit/find-panel-search-metadata)

## Access behavior and validation

Apple’s `NSPasteboard.AccessBehavior` documentation says: “access that is both user originated and paste related will always be allowed, and will not result in a notification.” Its default General-pasteboard behavior asks on programmatic access. This is narrower than the attachment’s blanket no-prompts claim; do not assume every button, timer, preview, or asynchronous read receives the explicit-paste treatment. [Access behavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum)

Availability is separate from enforcement rollout. The installed macOS 27.0 SDK’s `AppKit.framework/Headers/NSPasteboard.h` declares the enum and property with exact wording `API_AVAILABLE(macos(15.4))`. This does not prove identical enforcement on every macOS 15.4, 26.x, or later release. No rollout claim or release-by-release compatibility guarantee is established here.

Copy also has a system boundary: Apple states the general pasteboard “automatically participates with the Universal Clipboard feature in macOS 10.12 and later”. A local note-storage policy therefore cannot by itself establish local-only clipboard transfer. Copy law should address that boundary explicitly. [General pasteboard](https://developer.apple.com/documentation/appkit/nspasteboard)

**Proposed validation:** exercise keyboard/menu paste, sealed paste, any conversion command, deliberate drops and Services; include missing formats, multiple items, lazy data, unavailable data, and asynchronous completion. Record OS/build, signing and sandbox configuration, access setting, action origin, requested representation, and result. Test the minimum supported release and supported 26.x releases before publishing compatibility wording. The ADR and future copy/paste laws should decide allowed triggers, representation selection, transformations, failures, source attribution, and retained metadata; this research does not decide those rules.
